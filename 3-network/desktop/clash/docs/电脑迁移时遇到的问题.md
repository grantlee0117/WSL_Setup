## Clash Verge 链式代理配置问题总结

---

### 问题 1：脚本控制台报错 `expected value at line 1 column 1`

**现象：** 配置在老电脑正常，导入新电脑后 Script.js 无法运行

**原因：** 不同版本 Clash Verge 内置的 QuickJS 引擎对 UTF-8 中文字符处理存在差异，特别是中文注释和特殊框线符号（═、─、┌、└）会导致解析失败

**解决：** 删除脚本中所有中文注释和特殊符号，保持纯 ASCII 代码

---

### 问题 2：链式代理全局模式正常，规则模式失败

**现象：** 开启规则模式后浏览器无法访问任何网站（包括百度），但微信正常

**原因：** Clash Verge 界面的 DNS 覆写设置中 IPv6 是开启的，而链式代理的静态住宅节点不支持 IPv6，导致 DNS 返回 IPv6 地址后连接失败

**解决：** 关闭两处 IPv6 设置：
- Clash 设置 → IPv6 → 关闭
- DNS 覆写 → IPv6 → 关闭

---

### 问题 3：脚本中的 DNS 配置不生效

**现象：** 脚本里写了 `dns.ipv6 = false`，但实际没生效

**原因：** Clash Verge 的配置优先级是：`订阅 → Merge.yaml → Script.js → DNS 覆写（界面）`，界面设置会覆盖脚本配置

**解决：** 两种方案任选：
- 方案 A：关闭 DNS 覆写开关，让脚本配置生效
- 方案 B：保持 DNS 覆写开启，直接在界面调整（推荐，更直观）

---

### 问题 4：规则模式下主页 IP 显示中国，全局模式显示美国

**现象：** 实际访问外网正常走链式代理，ping0.cc 测出美国 IP，但 Clash Verge 主页 IP 信息显示中国

**原因：** 主页 IP 检测使用的域名没有命中 `静态住宅-链式代理` 规则，走了直连或普通代理

**解决：** 查看连接日志找到 IP 检测用的域名，将其加入 `rulesStrictIP` 规则中。这不会造成死循环，因为规则匹配是静态的，与 IP 检测结果无关

---

### 经验总结

| 要点 | 建议 |
|------|------|
| 脚本编写 | 避免中文注释，使用纯 ASCII |
| IPv6 | 链式代理场景下建议全部关闭 |
| DNS 配置 | 统一用界面设置，避免多处配置冲突 |
| 跨电脑迁移 | 确保 Clash Verge 版本一致，通过界面创建配置而非直接复制文件 |
| 配置文件迁移 | Merge、Script 等配置文件应复制代码内容粘贴，而非直接替换配置目录中的文件 |
