

## Shadowrocket 链式代理配置教程

### 一、核心概念理解

**Shadowrocket 的结构：**
- **首页**：按订阅/来源分组显示所有节点（机场订阅节点、本地手动添加的节点）
- **代理分组**：在配置文件中创建，用于规则分流指向
- **链式代理**：通过单节点的「代理通过」功能实现，不是通过配置文件的 relay 语法

**链式代理流量走向：**
```
设备 → 前置节点（一级跳） → 落地节点（家宽） → 目标网站
```

**默认流量走向：**
- 没有被规则命中的流量，最终由 `FINAL` 规则决定
- `FINAL,PROXY` → 走首页选中的节点（黄点标记）
- `FINAL,DIRECT` → 直连不走代理
- `FINAL,某代理分组` → 走指定的代理分组

**首页选中节点的作用：**
- 首页节点前面的黄点表示当前选中的节点
- 这个节点对应配置文件中的内置策略 `PROXY`
- 当规则指向 `PROXY` 或 `FINAL,PROXY` 时，流量走这个节点



### 二、完整配置步骤

#### 第一步：添加节点

1. **添加机场订阅**
   - 首页 → 右上角 + → 类型选择 `Subscribe` → 粘贴订阅链接 → 保存

2. **手动添加落地节点（家宽服务器）**
   - 首页 → 右上角 + → 类型选择 `Socks5`（或其他协议）
   - 填写服务器地址、端口、用户名、密码
   - 备注命名（如：原生静态住宅IP-美国洛杉矶）
   - 保存（节点会出现在「本地节点」分组）

#### 第二步：创建代理分组

1. **进入配置编辑**
   - 配置 → 点击配置文件右侧 (i) → 代理分组 → 右上角 +

2. **创建一级跳分组（自动选择最快节点）**
   - 名称：`美日一级跳`
   - 类型：`url-test`
   - 添加订阅：勾选所有机场订阅
   - 正则过滤：`美国|日本|JAPAN|UNITED STATES`
   - 保存

3. **创建落地节点分组**
   - 名称：`美国洛杉矶-家庭宽带`
   - 类型：`select`
   - 添加节点：只勾选「原生静态住宅IP-美国洛杉矶」
   - 保存

#### 第三步：配置链式代理（关键步骤）

1. **设置节点的「代理通过」**
   - 首页 → 找到「原生静态住宅IP-美国洛杉矶」节点
   - 点击节点右侧 (i) → 找到「代理通过」
   - 选择「美日一级跳」分组
   - 保存

#### 第四步：添加分流规则

1. **编辑配置文件纯文本**
   - 配置 → 点击配置文件 → 编辑纯文本

2. **在 `[Rule]` 部分添加规则**
   ```
   # AI 服务走链式代理
   DOMAIN-SUFFIX,openai.com,美国洛杉矶-家庭宽带
   DOMAIN-SUFFIX,anthropic.com,美国洛杉矶-家庭宽带
   DOMAIN-SUFFIX,claude.ai,美国洛杉矶-家庭宽带
   ```
   
3. **规则放在 `[Rule]` 最前面**（规则从上往下匹配，先匹配先生效）

4. **保存配置**

#### 第五步：启用并测试

1. 首页开启代理连接
2. 访问 https://ipinfo.io 确认出口 IP 是家宽 IP
3. 查看日志（数据 → 代理）确认规则命中正确的代理分组

### 三、踩坑记录与解决方案

| 坑 | 现象 | 原因 | 解决方案 |
|---|---|---|---|
| **relay 语法无效** | 配置文件写了 `链式代理 = relay, A, B`，但规则不走链式代理 | Shadowrocket 不支持 Clash 的 relay 语法 | 使用节点的「代理通过」功能实现链式代理 |
| **模块无法注入代理分组** | 模块启用后，首页看不到模块里定义的代理分组 | Shadowrocket 模块对 `[Proxy Group]` 支持有限 | 直接在主配置文件中添加代理分组 |
| **配置被自动更新覆盖** | 自定义的代理分组和规则被远程配置覆盖 | 配置文件有 `update-url`，会定期自动更新 | 注释掉 `update-url` 行（前面加 `#`） |
| **规则不生效** | 日志显示命中了其他规则，不是自定义规则 | 规则优先级问题，自定义规则放在了后面 | 自定义规则放在 `[Rule]` 最前面 |
| **配置修改后不生效** | 改了配置但行为没变化 | 配置未重新编译/加载 | 关闭代理 → 点击配置文件 → 使用配置 → 重新开启代理 |
| **正则过滤语法错误** | 代理分组筛选不到节点 | 使用了中文符号或错误的正则语法 | 使用英文竖线 `|` 分隔关键词，如 `美国|日本` |

### 四、配置文件结构参考

```ini
[General]
ipv6 = false
bypass-system = true
dns-server = https://dns.alidns.com/dns-query
# update-url = ...  # 注释掉防止被覆盖

[Proxy Group]
美国洛杉矶-家庭宽带 = select,原生静态住宅IP-美国洛杉矶
美日一级跳 = url-test,订阅1,订阅2,use=true,interval=600,policy-regex-filter=美国|日本

[Rule]
# 自定义规则放最前面
DOMAIN-SUFFIX,openai.com,美国洛杉矶-家庭宽带
DOMAIN-SUFFIX,claude.ai,美国洛杉矶-家庭宽带
# ... 其他规则
GEOIP,CN,DIRECT
FINAL,PROXY
```

**典型流量分配逻辑：**
```
自定义规则命中 → 走指定代理分组（如家宽链式代理）
GEOIP,CN → 直连
FINAL,PROXY → 走首页选中的节点
```

### 五、验证链式代理是否生效

1. **IP 检测**：访问 https://ipinfo.io，显示的应该是家宽 IP
2. **日志检查**：数据 → 代理 → 搜索域名，确认命中的策略是「美国洛杉矶-家庭宽带」
3. **实际测试**：访问 ChatGPT、Claude 等服务，能正常使用说明链式代理生效
